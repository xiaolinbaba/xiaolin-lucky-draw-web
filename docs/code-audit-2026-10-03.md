## 已完成的修复

| 问题 | 修复 | 位置 |
| --- | --- | --- |
| 抽奖提示组件使用 `innerHTML`，用户填写的奖项名称可能成为可执行 HTML | 对完整提示消息进行 HTML 转义，奖项名称按原文显示；增加恶意 HTML 回归测试 | `src/utils/html.ts`、`src/views/Home/index.vue` |
| 脚本 CSP 允许任意内联脚本 | 删除 `script-src` 的 `unsafe-inline`；保留已有统计脚本来源，并允许应用内嵌字体 | `public/_headers` |
| Excel 列名映射会读取对象继承属性，特殊列名可能改变映射行为 | 检查映射表自身属性，使用无原型的行对象 | `src/views/Config/Person/PersonAll.vue` |
| 每次卡片样式更新都可能叠加鼠标事件监听，旧颜色闭包也会继续执行 | 用可替换的事件处理函数保持单份监听，并验证连续更新后使用最新颜色 | `src/hooks/useElement.ts` |
| Three.js 场景及对象进入 Vue 深层响应式代理，增加逐帧访问开销 | 改用 `shallowRef` 保留原始类实例；动画统一逐帧渲染，避免多个相机补间重复渲染 | `src/views/Home/index.vue` |
| 只展示有限卡片，却先序列化和复制整个名单 | 仅复制实际展示的人员卡片，不修改原始人员 ID 和中奖信息 | `src/views/Home/index.vue` |
| 关闭头像显示后仍给图片赋值，可能发起无用的外部图片请求 | 头像隐藏时不设置图片来源 | `src/views/Home/index.vue`、`src/hooks/useElement.ts` |
| 多人中奖时，对每位中奖者重复扫描整份名单 | 按 ID 建立一次索引，保留相同中奖记录及写入顺序 | `src/store/personConfig.ts` |
| 庆祝动画的自定义帧循环没有在页面退出时取消 | 跟踪并取消庆祝动画帧，继续调用粒子库的清理逻辑 | `src/views/Home/index.vue` |
| 暂停或切换音乐后，旧的异步存储读取可能重新启动播放；组件卸载未停止音频 | 用播放请求序号忽略过期读取；卸载时暂停、移除音频来源并释放资源 | `src/components/PlayMusic/index.vue` |
| 图片和音乐列表扫描会读取全部大文件内容；奖项页还加载了未使用的图片数据 | 列表同步仅读取存储键；移除无用的图片读取及重复深层监听 | 图片、音乐和奖项配置页面 |
| 全局挂载整个 Three.js 库，但项目没有使用此挂载 | 移除全局挂载，首页改为按路由加载 | `src/main.ts`、`src/router/index.ts` |
| 小列数布局下，旧图案位置可能超出卡片数组范围 | 检查实际卡片存在后再更新颜色；空名单不进入抽奖动画 | `src/views/Home/index.vue` |
| 国际化初始化在读取本地存储时可能抛出异常 | 将存储读取移入现有异常处理范围 | `src/locales/i18n.ts` |

第三方类实例使用浅层响应式的处理依据：[Vue 官方说明](https://vuejs.org/api/reactivity-advanced.html#shallowref)。

这些工具处理仓库中的源文件，不参与浏览器运行，也不用于解析用户上传的 Excel 或媒体文件。建议后续迁移旧 SVG 构建链并清理 Vue 2 编译依赖，独立验证图标输出；不强制将 PostCSS 5 替换为不兼容的大版本。

## 后续授权并完成的 UI 与其他改进

- 人员及中奖名单默认每页 50 条，可选择 25 / 100 条，删除最后一页记录后自动回到有效页；导出保持完整名单。
- Excel 导入移到可终止的后台线程，限制 10 MB、20,000 人、50 列、50 MB 实际解压内容，15 秒超时；完整校验后再替换，现有名单覆盖需确认。较大分批数量使用数字分界编辑，避免渲染数万个刻度。
- 删除全部奖项、音乐及恢复默认配置使用统一确认弹窗，说明影响范围；音乐和整体重置等待存储操作完成，失败时保留弹窗并提示。
- 列数为 1–100、卡片尺寸为 20–1,000、文字大小为 8–200，均校验整数并保留上次有效配置。原文字大小修改未写回 store 的问题一并修复。
- 媒体上传和删除增加忙碌状态、失败提示和可用容量估算；存储删除成功后才移除列表项目，失败可重试；删除图片时清理对应奖项和背景引用。
- 新增完整 JSON 备份，包含人员、中奖历史、奖项、界面配置及上传媒体。恢复限制 200 MB，校验格式、范围和媒体完整性，确认覆盖范围并下载当前备份后再写入；写入失败尝试恢复旧值，回滚失败时明确提示保留两份备份。整体重置同样先备份并使用可回滚写入。
- 损坏或结构异常的本地配置使用默认状态，原始数据在覆盖前保存为恢复副本，可从界面设置导出；存储失败有全局提示，不再因 JSON 解析异常阻断启动。
- Docker 使用根路径静态资源与 History 回退，缺失静态资源返回 404，固定 pnpm 版本并使用锁文件安装；README 的 Node / pnpm 要求、导入限制、备份规则同步更新。
